# Netcontroll

مدیریت مسیر اتصال در Windows 10/11 x64 با رابط فارسی. توسعه‌دهنده **peymanarjmand**.

## نصب و استفاده

فایل `dist/Netcontroll-Setup.exe` را در File Explorer اجرا کنید. «نصب برنامه» یا دکمهٔ به‌روزرسانی را بزنید و پس از نمایش «نصب انجام شد»، «باز کردن برنامه» را انتخاب کنید. میان‌بر دسکتاپ اختیاری است. در به‌روزرسانی، فایل‌های نسخهٔ قبلی جایگزین می‌شوند و قوانین شبکه و نام سرورها حفظ می‌شوند. بسته فقط فایل‌های برنامه را حمل می‌کند و از ‎.NET Framework‎ موجود در ویندوز استفاده می‌کند. نصب برای کاربر فعلی است. برنامه با بستن پنجره کنار ساعت می‌ماند. از منوی همان آیکون می‌توانید خارج شوید. برای اجرای مستقیم، پوشهٔ کامل `build/payload` لازم است.

- **دامنه‌های Chrome** — برای دامنه و در صورت نیاز زیردامنه‌ها مسیر انتخاب کنید. دقیق‌ترین قانون فعال برنده است. Chrome مدیریت‌شده با یک پروفایل جدا باز می‌شود. برای پروفایل روزمره دکمهٔ «اتصال Chrome فعلی» راهنمای نصب افزونهٔ محلی را باز می‌کند. افزونه به‌صورت صریح از تنظیمات پراکسی پروفایل استفاده می‌کند. قبل از خروج کامل یا حذف برنامه، از دکمهٔ افزونه اتصال را قطع کنید. دامنه‌های بدون قانون از سوکت معمول ویندوز استفاده می‌کنند. سیاست بر میزبان هر درخواست وب اعمال می‌شود. درخواست‌های یک تب به CDNهای دیگر به قانون همان CDN نیاز دارند. WebRTC، UDP، DNS و صفحه‌های داخلی Chrome خارج از پراکسی HTTP هستند. DNS از حل‌کنندهٔ ویندوز استفاده می‌کند.
- **IP** — نام سرور و IPv4 را وارد کنید. افزودن، حذف و تغییر مسیر با UAC انجام می‌شود. مسیرها در سطح سیستم و برای همهٔ پورت‌ها هستند. کار زمان‌بندی‌شده هنگام بوت، تغییر شبکه و هر دو دقیقه مسیرها را بازبینی می‌کند. قواعد فایروال روی آداپتورهای شناسایی‌شده مانع خروج از مسیر مخالف می‌شوند. انتقال تنظیمات قدیمی به تأیید کاربر نیاز دارد.
- **Docker Desktop** — یک بار آدرس `http://127.0.0.1:17832` را در تنظیمات Containers proxy برای HTTP و HTTPS وارد کنید. سپس مسیر اتصال‌های جدید را با یک کلیک تغییر دهید. آزمون دانلود، هم کد خروج Docker و هم مشاهدهٔ اتصال در پراکسی را بررسی می‌کند. رفتار دستورهای داخل build و کانتینر به تنظیمات پراکسی آن محیط بستگی دارد. روی موتور Docker راه دور یا ترافیک دلخواه UDP اعمال نمی‌شود.
- **برنامه‌ها** — فایل EXE را انتخاب کنید. هر برنامه یک پورت محلی جدا دارد. دکمهٔ اجرا متغیرهای HTTP_PROXY / HTTPS_PROXY / ALL_PROXY را به فرایند تازه می‌دهد. برای برنامه‌هایی با تنظیم پراکسی داخلی، نشانی را کپی کنید. برنامه‌های فاقد پشتیبانی پراکسی یا فرایند از قبل باز ممکن است این تنظیم را نپذیرند. صفحهٔ فعالیت مشاهدهٔ اتصال را نشان می‌دهد.
- **فعالیت اتصال‌ها** — آخرین ۱۲۰ اتصال پراکسی در حافظه نگه‌داری می‌شود. HTTPS از CONNECT عبور می‌کند و گواهی ویژه‌ای نصب نمی‌شود. «فقط VPN» و «اینترنت عادی» برای اتصال‌های پراکسی IPv4 به اینترفیس و آدرس مبدأ مقید می‌شوند. اگر رابط لازم موجود نباشد، اتصال خطا می‌دهد. مسیر سیستم از IPv4 و IPv6 پشتیبانی می‌کند.

قوانین کاربر در `%LOCALAPPDATA%\Netcontroll` و تنظیمات تأییدشدهٔ سیستمی در `%ProgramFiles%\Netcontroll Routes` ذخیره می‌شوند. برای بازگرداندن پراکسی‌های Docker و Chrome قبل از حذف، تنظیمات قبلی را انتخاب کنید. حذف از Installed apps ویندوز انجام می‌شود.

## اسکن و کنترل مسیر

در صفحهٔ IP، «اسکن قوانین ویندوز» تنظیمات قبلی همین لپ‌تاپ، مسیرهای فعال و مسیرهای IPv4 ذخیره‌شده را می‌خواند. برای هر مورد می‌توانید نام دلخواه بگذارید. نام‌گذاری در حساب کاربری ذخیره می‌شود. حذف مسیر ذخیره‌شده مشخصات همان IP، دروازه، رابط و هزینهٔ مسیر را قبل از حذف دوباره بررسی می‌کند. مسیرهای موقت با منشأ نامشخص برای مشاهده و نام‌گذاری نمایش داده می‌شوند. حذف قوانین منتقل‌شده در Netcontroll اعمال می‌شود؛ حذف کامل نرم‌افزار، مدیریت قدیمی را در صورت انتقال دوباره فعال می‌کند.

در مدیریت برنامه‌ها، «قفل فایروال» اختیاری است. این گزینه خروج فایل اجرایی انتخاب‌شده روی آداپتورهای مخالف را برای همهٔ پروتکل‌ها مسدود می‌کند. برنامه‌ای که پراکسی را نمی‌پذیرد ممکن است در این حالت اتصال نداشته باشد. فایل اجرایی فرعی به قانون خودش نیاز دارد.

افزونهٔ پروفایل روزمرهٔ Chrome فقط دامنه‌های دارای قانون را به پراکسی محلی می‌فرستد. تغییرات را از برنامه دریافت می‌کند. پنجرهٔ «Chrome مدیریت‌شده» تمام درخواست‌های وب آن پروفایل مجزا را به سرویس محلی می‌فرستد و برنامه مسیر هر میزبان را تعیین می‌کند.

## ساخت

روی ویندوز x64 با .NET Framework 4.8 و Visual Studio Build Tools (MSBuild و Roslyn) در ریشهٔ پروژه `powershell -NoProfile -File .\build.ps1` را اجرا کنید. وابستگی NuGet یا سرویس ابری لازم نیست. فایل نصب خروجی در `dist` است. فایل‌های ساخت، داده‌های کاربر و کلیدهای امضای کد در Git قرار نمی‌گیرند.

## آزمون

- `node --test tests/chrome-policy.test.cjs` انتخاب مسیر دامنه در افزونه را بررسی می‌کند.
- `powershell -STA -File tests/Smoke.ps1` بستهٔ نصب، رابط WPF، تطبیق دامنه و به‌روزرسانی قوانین را بررسی می‌کند. با `-Live` به Chrome، OpenVPN فعال و دسترسی به api.ipify.org نیاز دارد. با `-Container` از ایمیج محلی ذکرشده در اسکریپت استفاده می‌کند.
- `tests/WindowsRoutes.ps1` در Windows PowerShell مدیر، روی سیستمی بدون تنظیم فعال Netcontroll و با OpenVPN روشن اجرا می‌شود. این تست از یک IP رزروشده استفاده می‌کند و پس از اجرا قواعد تست را حذف می‌کند.
